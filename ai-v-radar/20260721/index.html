what's the difference between a loop and a graph? (marketing edition) both are ways to run an agent, the difference is who decides the path, the agent or you. a loop still starts with you. you set the goal, the brief, and the bar it has to clear. what the agent owns is the path. take writing an SEO article: hand it the brief and it drafts, reads the draft back against that brief, rewrites the weak parts, checks again, and keeps circling until it clears the bar. the one thing you did not write is the step-by-step it took to get there. a graph is you drawing the steps and the routes between them ahead of time. same article, but now you set the map: research the keyword and the competitors ranking for it. draft from what you find. score that draft against your rubric. if it clears, add the internal links and publish. if it misses, back to the draft. the agent still decides how to handle each step, it just travels the routes you laid down. the shape of this has a name, a state machine. every node is a state the work can be in, and a check at each one decides where it goes next, forward when it clears or back to an earlier node when it misses. if you have built a workflow in n8n, you have already drawn one. nodes wired together, branches that fire on a condition, a step that loops until it clears, that picture is a graph. an agent graph is the same shape, the nodes hold agents doing the work instead of single api calls. the way I think about it, a graph is a map of loops and checkpoints. some nodes run once, others are their own loop where the agent works something out, and the checkpoints between them read the result and route the work. you keep laying down nodes and checkpoints until the map reliably gives you the output you want. the vault accelerator I run at my agency is one of these maps, 3 sessions that hand off in a fixed order: > research session: reads our company brain and past campaign results, pulls in competitor and market context, and builds the cohort we go after > landing page session: takes that research and builds the page from it > content session: uses the research and the page to write the copy, illustrations, and slides for the live sessions we run inside the content session runs a loop, a critic scores each draft against a rubric and sends it back until it clears the bar. that is one node on the map, the checkpoints between the sessions carry the work from one to the next a graph earns its extra setup on anything you run every week: > validation gates the work cannot skip > a fixed set of routes the job can take > a clear failure point, you see the exact step something broke on a loop on its own is enough for the work you only do once, where you don't know the path yet, let the agent find it. graphs earn their place on the jobs you repeat, the content pipeline, the SEO and AEO funnel step by step, the vault accelerator once the map works you reuse it, feed it the next cohort and the whole pipeline runs again past the loop, the next thing you design is the map it runs inside.

循环和图有什么区别？（营销版） 两者都是运行智能体的方式，区别在于路径由谁决定：智能体，还是你。 循环仍然从你开始。你设定目标、简报和必须达到的标准。智能体负责的是路径。 以写一篇 SEO 文章为例：你把简报交给它，它会起草、对照简报回读草稿、重写薄弱部分、再次检查，并不断循环，直到达到标准。你唯一没有写的是它达成目标所走的具体步骤。 图则是你提前画好步骤，以及步骤之间的路线。同样是那篇文章，但现在由你设定地图：研究关键词和排名靠前的竞争对手。根据发现起草。按你的评分标准评估草稿。 如果达标，就添加内部链接并发布。如果没达标，就回到草稿。智能体仍然决定如何处理每一步，只是沿着你铺好的路线前进。 这种结构有个名字，叫状态机。每个节点都是工作可能处于的一种状态，每个节点上的检查决定下一步去哪里：达标就前进，没达标就退回到前面的节点。 如果你在 n8n 里搭过工作流，其实你已经画过一个了。节点连接在一起，分支按条件触发，某个步骤循环直到达标，那张图就是一个图。智能体图也是同样的形态，只是节点里放的是执行工作的智能体，而不是单个 api 调用。 我的理解是，图就是循环和检查点的地图。有些节点只运行一次，另一些节点本身就是一个循环，智能体会在里面把事情处理好；节点之间的检查点读取结果并路由工作。你不断铺设节点和检查点，直到这张地图能稳定产出你想要的结果。 我在机构里运行的 vault accelerator 就是这样一张地图，由 3 个按固定顺序交接的 session 组成： > research session：读取我们的公司大脑和过往活动结果，引入竞争对手和市场背景，并构建我们要触达的人群 > landing page session：接收研究结果，并据此构建页面 > content session：利用研究结果和页面，撰写我们直播 session 所需的文案、插图和幻灯片 content session 内部运行着一个循环，评论器会按评分标准评估每版草稿，并把它退回去，直到达标。这是地图上的一个节点；session 之间的检查点把工作从一个环节带到下一个环节。 图在你每周都要运行的事情上值得投入额外设置： > 工作不能跳过的验证门 > 任务可以走的一组固定路线 > 清晰的失败点，你能看到到底是哪一步出了问题 对于只做一次、你还不知道路径的工作，单独一个循环就够了，让智能体自己找到路径。图适用于重复性的任务：内容流水线、SEO 和 AEO 漏斗的逐步推进、vault accelerator。 一旦地图跑通，你就可以复用它，输入下一批人群，整条流水线再次运转。 越过循环之后，你要设计的下一个东西，就是它运行其中的那张地图。

This is awesome. Instead of doing work this morning, I spent some time brushing up on math to provide a handwavy overview to anyone else who like me doesn't have a math background and is rusty: At a distance, the conjecture is basically that if a n-dimensional polynomial function (e.g. F(x, y, z) map to some output (x', y', z')) meets some special conditions, then 1) it is invertible, and 2) the inverse is polynomial. Disproving the conjecture requires finding a n-dimensional polynomial function that meets these special conditions, but is either 1) not invertible at all, or 2) is invertible but not polynomial. (2) is actually not a possibility due to some other math theorem - if there is an inverse, the inverse has to be polynomial. Invertibility just means the function can be "undone" at every single input point - if input (x1, y1, z1) maps to output (x2, y2, z2), then output (x2, y2, z2) can map to input (x1, y1, z1). A function is not invertible if multiple input points (x, y, z)'s map to the same output (x, y, z) Here Fable 5 presumably did some search and found a function that was not invertible. That function is this: F(x, y, z) = ( z(1+xy)^3 + y^2(1+xy)(4+3xy), y+3x(1+xy)^2z + 3xy^2(4+3xy), 2x-3x^2y-x^3z ) This function meets the special conditions (jacobian determinant is a non-zero constant for every point), but has multiple input points that map to the same output: Inputs: (0, 0, -1/4), (1, -3/2, 13/2), and (-1, 3/2, 13/2) all map to the same output: (-1/4, 0, 0) ----- The Jacobian is the multivariable version of a derivative, so it is a function of a specific input point. When the Jacobian determinant is non-zero at a specific input point, there is local invertibility around that point. This conjecture was stronger in that if it was non-zero (and constant, due to being over the complex numbers, which I don't quite get and I ran out of time to understand), then the function is globally invertible. ----- What's interesting here is that finding counterexamples seem like the type of math work that agentic models excel at. It involves generating and crawling a large search space, using priors to narrow it down, and a bit of brute force and raw compute power. Machines can process a wide set of possibilities faster than humans, which is helpful for finding counterexamples.
