科研 Agent 最尴尬的场景，可能是第二天重新开工时： 它已经不记得昨天为什么放弃那条路线了。 Épi 想解决的，就是这种长期科研里的「断片」。 它把研究状态放到模型上下文之外长期保存，包括正在跑的实验、代码、失败路线、关键结论和之前为什么做出某个决定。 同时，Agent 可以开多个 Branch 探索不同方法，效果不好就回退到旧版本，再从另一个岔路继续走。 所有结果最后都交给固定 Verifier 检查，避免研究过程中不断变化的方法把评估标准也一起带偏。 这套机制最终产生了 120 个 record-setting results，包括 20 个数值边界纪录和 100 个构造纪录。 其中 n-queens constant 的区间缩小约 84 倍，quartic Feigenbaum attractor dimension 的严格区间缩小超过 360 万倍。 轻量版 Épi-turbo 在 30 个 FrontierOR 任务上，总分比 Codex 高 5.4%，模型成本只有 64%。 Épi值得称赞的地方是它没有把「长期科研」理解成让 Agent 一次跑得更久。 因为下一次回来时，它还知道自己做过什么、为什么失败，以及有哪些旧路线值得重新捡起来。 科研很多时候，就是这样一点点从岔路和失败里长出来的。 📎 arxiv: https://t.co/v0oddLp0r8

We next asked whether CONCERT can predict how the response to a gene knockout depends on where it occurs in a tumor. Perturb-Map uses CRISPR to knock out genes in mouse lung tumors and tags each tumor, so you can identify the knockout in every lesion while spatial transcriptomics measures gene expression across the tissue. We studied Tgfbr2, Ifngr2 and Jak2, genes in the TGF-β and interferon pathways. When we place a Jak2 knockout patch into the tumor core or into normal tissue, the predicted spots move toward the measured Jak2 knockout profile. CONCERT predicts that Tgfbr2 responses depend most on the surrounding niche and Jak2 responses least, and it outperforms five baselines. Spatial models let us choose where in a tissue to perturb as well as which gene to target. Alexander Swerdlow@alexjswerdlow

In language models, turning a generative model into a critic is simple: pass in the output and prompt for a score. Robot policies can't do this - they output physical actions & there's no built-in vocabulary to predict scores. So when it comes to RL on robot policies, we typically train a separate critic from sparse rewards - blind to everything the policy learned from the actions in the pretraining data. We think this has it backwards - can a critic learn from those actions the way the policy does? (1/n)

对于语言模型，把生成模型变成评估器很简单：输入生成结果，再提示它打分。机器人策略做不到这一点——它们输出的是物理动作，也没有用于预测评分的内置词表。 因此，对机器人策略进行强化学习时，我们通常会用稀疏奖励单独训练一个评估器，而它无法利用策略从预训练数据的动作中学到的知识。 我们认为这个思路反了：评估器能否像策略一样，从这些动作中学习？（1/n）

We first asked whether CONCERT can predict how a perturbation response unfolds over time DSS colitis is a standard mouse model of inflammatory bowel disease. Mice drink dextran sodium sulfate, which damages the colon lining and causes inflammation that later resolves. Profiling the tissue requires collecting it, so each mouse contributes a single time point CONCERT takes one day 0 slide and predicts the same colon at days 3, 9 and 21. Inflammatory markers such as Il1b and Cxcl10 peak at day 9 and decline by day 21, in line with measured mice, and the predictions show which mice respond more strongly This is counterfactual generation along time that generates a longitudinal view of each mouse from one sample

我们首先研究 CONCERT 能否预测扰动引发的响应如何随时间变化。 DSS 结肠炎是研究炎症性肠病的标准小鼠模型。小鼠饮用葡聚糖硫酸钠后，结肠黏膜受损并引发炎症，随后炎症逐渐消退。组织分析需要取材，因此每只小鼠只能提供一个时间点的数据。 CONCERT 只需一张第 0 天的组织切片，就能预测同一结肠在第 3、9 和 21 天的状态。Il1b 和 Cxcl10 等炎症标志物在第 9 天达到峰值，到第 21 天下降，与小鼠实测结果一致；预测还能显示哪些小鼠的反应更强烈。 这种沿时间维度的反事实生成，能从一个样本生成每只小鼠的纵向变化图景。

补充一点：合并 Subagent 最大的风险是在评测时候，分数没掉，而在某个任务悄悄挂了。 判断要不要保留一个 Subagent，我会问两个问题：它需要一个干净的 Context 吗？它的结论需要独立于主 Agent 吗？两个都是否，就可以考虑合回去。 合并前后怎么用 Eval 抓这种回退，我之前拆过 Anthropic 那篇，做 Agent 工程的可以一起收藏 👇 https://t.co/qAAZXYP0vX

Xudong Han@Xudong07452910

评测分数涨了，Agent 实际却没变好。做 Eval 最怕的就是这种「假进步」，而且它往往不是 Prompt 的问题，是 Eval 本身的问题。 Anthropic 这篇工程博客讲的就是怎么避免它，还把整套流程做成了 Claude Code 的两个命令。 ① /claude-api build-eval 自动构建评估集，优先从真实任务和失败案例中选题，还会检查评分器是否稳定。同一份输出判两次，如果结果不一致，就得先检查 Eval。 ② /claude-api hillclimb 让 Claude 自动改进 Prompt、Skill 或 Harness，每轮提出一项修改，再用训练集和留出测试集验证。 如果训练集分数涨了，测试集却没提升，就撤回修改，避免 Agent 只记住几个失败案例。 而且当连续优化没有效果时，它还会反过来检查 Eval 本身有没有问题，比如题目含糊、评分规则写错。 实际案例中，他们在 44 个客服工单上做优化，最终把单次成本降到了约 1/5，留出集准确率从 78.6% 提升到 90.5%。不过样本量不大，还不能直接推广。 我觉得最值得抄的是两步：评分器判两次看是否一致，以及优化卡住时让 Agent 反过来质疑 Eval。评分器自己都不稳，后面分数的涨跌就没有意义。 但有一点要注意：每轮都用测试集决定是否保留修改，测试集其实也在参与调参。如果用它跑自动 hillclimb，我会额外留一份完全没碰过的数据，在那份数据上不涨，就说明是在给测试集调参，该回滚。 做 Agent Eval、或者正在手动调 Prompt 和 Skill 的，建议先收藏。 原文：https://t.co/rBxLiS1CjA

"Symbolic learning" is simply "machine learning" (automatically learn function x -> y given examples of (x, y) pairs), but where the substrate is symbolic, i.e. the functions you learn are code-like, not curve-like. The term is in opposition to "parametric learning" or "curve-fitting". Symbolic learning does not mean that the system avoids numbers or probabilities. It means its learned representation are discrete, explicit, parsimonious, code-like.

“符号学习”其实就是“机器学习”（给定一些 (x, y) 样本，自动学习函数 x -> y），只不过其底层载体是符号化的，也就是说你学到的函数更像代码，而不是曲线。 这个术语是相对于“参数学习”或“曲线拟合”而言的。 符号学习并不意味着系统避开数字或概率。它意味着学到的表示是离散、显式、简约、类似代码的。
