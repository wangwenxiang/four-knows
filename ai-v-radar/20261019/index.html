Introducing ExtractBenchPro: the most challenging benchmark for real-world document extraction. We see a massive long tail of document complexity in terms of use cases brought on from our customers, that are completely unsolved from a price-performance standpoint. These include trial balances, well logs, canvass binders, site plan reviews, duty reconciliations, loss runs, and more. Most existing extraction benchmarks are saturated by the frontier models (our cheapest modes now score 93%+ on ExtractBench). So there is enormous economic value in building a complex extraction benchmark that reflects this long-tail of knowledge work. We spent a long time curating the most complex elements that we saw from real world extraction use cases: ✅ Document conventions: containing legends or rules where the rest of the document should be interpreted ✅ Density of internal jargon: specific definitions that must be cross-referenced within a doc ✅ Aggregation and reasoning: beyond returning exact values on a page, infer values derived from aggregating multiple sources of information ✅ Drawn relations: complex diagrams like procedures and circuits ✅ Charts inside documents: read precise points within a chart ✅ Long chart sheets: some data series like well logs cram all this data into an extremely long page Within the industries where document extraction is relevant, even small mistakes can have enormous negative impacts. Therefore our headline evaluation metric is based on perfect documents: the proportion of docs with perfect (100%) value f1 score. (Besides this we also measure value f1 and grounded f1) It’s an extremely hard task for even the latest frontier models to solve, topping out at ~58% or so in Value F1 score for Codex with Astra - which is quite good but extremely expensive (almost $1 per page!) Our LlamaParse agentic/agentic plus modes are 20-40% and cover the left side of the Pareto frontier, at price ranges that are feasible for full production use. Agent 最危险的时刻，可能恰恰是它停下来等你点「确认」的时候。 因为很多长时任务跑到这一步，人其实已经跟不上前面的过程了。 Margaret Mitchell 等人这篇《AI Agents Push Humans Out of the Loop》，讨论的就是这个问题。 Agent 越自主，人越容易逐渐失去上下文。几十步工具调用、状态变化和连续审批之后，很容易出现 approval fatigue： 按钮还在点，真正的判断已经开始掉线。 长期依赖自动化还会带来另一个问题：人的领域能力和接管能力可能慢慢退化。 所以 Human-in-the-loop 真正要解决的，不只是「流程里有没有人」，而是关键时刻这个人是否还理解系统正在做什么。 论文建议减少无意义审批，把人的注意力集中到真正高风险的节点，同时提供更好的状态恢复、权限边界和批量 review。 这篇让我对 Human-in-the-loop 有了一个更现实的理解： 人不是最后一道按钮。 人得始终保留接管系统的能力。 📎 arxiv: https://t.co/HneMWkoNxk
