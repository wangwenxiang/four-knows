Codex 自动压缩近乎无缝，并提供百万 token 上下文选项

引用｜下面是在 Codex 中为 GPT-5.6 Sol 启用 100 万 token 上下文窗口的方法。 虽然我们已经把 Codex 的上下文限制调到兼顾性能和成本的最佳设置，但这是一个常见需求，所以这里记录一下。 更大的上下文窗口可以让 Codex 在总结旧内容之前保留更多代码、工具输出和对话历史。你需要使用支持该能力的模型。例如，GPT-5.6 Sol 的文档中标明其窗口为 1,050,000 token。 打开 ~/.codex/config.toml，并在所有 [section] 标题之前的顶层添加或更新以下设置： ``` model = "gpt-5.6-sol" model_context_window = 1000000 model_auto_compact_token_limit = 900000 ``` 第一项选择模型。第二项告诉 Codex 使用 100 万 token 的上下文预算。第三项会在约 900,000 token 时启动自动历史压缩，留出一些余量。保存后重启 Codex 客户端并开启新会话。 如果想在单次 CLI 会话中试用该配置，而不更改默认设置： ``` codex -m gpt-5.6-sol \ -c model_context_window=1000000 \ -c model_auto_compact_token_limit=900000 ``` 祝你玩得开心，但也请知道，我们对默认设置是经过仔细调优的！
