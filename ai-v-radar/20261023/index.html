P0LLM / AI Agents10-22 11:35 北京

Agent Harness 也开始学「面向对象编程」了。 Google Cloud AI Research 和 UIUC 这篇 OO-Harness，把 Harness 组织成一棵可以持续进化的类继承树。 不同任务需要的执行策略并不一样。与其不断修改一套全局 Harness，OO-Harness 会先从执行轨迹里找到相似的失败模式，再为这类任务生成一个专门的子类。 公共能力从父类继承，特殊需求只改对应方法。 到了新任务，Router 会先观察基础 Harness 的执行轨迹，再决定继续用 Base，还是切到某个专用 Harness。 这个设计还有一个挺实用的好处： 遇到完全陌生的 OOD 任务时，Router 可以直接退回原始 Base，避免之前学到的「优化」反过来拖累新任务。 实验覆盖 AutomationBench、Workspace-Bench 和 Toolathlon-GYM，OO-Harness 三项都拿到最佳结果。 其中 AutomationBench 从 61.62 提升到 77.41；消融里，真正使用继承结构也比扁平复制 Harness 高近 5 个百分点。 这样的话，Harness 开始有了「分支」和「继承」。 以后面对越来越复杂的任务，Agent 可能不会再共用一套万能工作流。 它的运行系统会像软件架构一样，逐渐长出不同分支，再根据任务选择最合适的一条。 📎 arxiv: https://t.co/aWESW1MpQc

P0LLM / AI Agents10-22 19:20 北京

一个错误如果被 Agent 总结成 Skill，下一次它可能会更自信地再犯一遍。 《More Memory, Worse Agents》研究的就是这种 Error Reproduction。 很多 Agent Memory 会把过去轨迹总结成规则和经验，再用于后续任务。问题在于，一旦总结本身出了偏差，错误也会跟着长期保存，并继续影响之后的决策。 作者因此提出 Anti-Persistence： 真实轨迹和结果可以长期保存，但抽象出来的规则和策略只在当前任务临时生成，用完就丢。下一次再根据新的上下文重新总结。 实验覆盖 ALFWorld、WebShop 和 ScienceWorld。Anti-Persistence 在 9 个模型×任务组合里拿到 7 个最好结果，平均成功率 59.9%，同时 LLM 调用成本最低。 长期保存，并不天然等于长期学习。我的判断是：该长期存的是事实（轨迹和结果），而不是结论（规则和策略）。结论随时可以重新算，存错了却很难发现。 做 Agent Memory 或 Skill 自进化的可以先收藏。我会先检查自己的 Memory 里存的是原始轨迹还是总结出的规则；如果是规则，至少给每条记上来源轨迹，出错时能追回去。 如果某类错误在接入 Memory 之后反而更频繁了，先怀疑的就该是那几条总结出来的规则。 📎 arxiv: https://t.co/KMxS6D357B
