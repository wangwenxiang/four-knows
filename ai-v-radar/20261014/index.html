Deep Research 跑到 1 亿 token 语料库时，最先崩的往往是「证据管理」。 搜得越久，两个问题会很明显： 已经找到的关键证据被埋掉，后来的修正也没真正进入最终结论；同时 Agent 还在继续搜索，越搜越长，却不知道自己到底还缺什么。 这篇 LongHarness 就是专门解决这个问题。 它维护两套持续更新的状态： EvidenceBank 保存已经确认的证据和来源； Conclusion State 记录当前结论，以及还有哪些信息缺口没解决。 新的证据会更新结论，新的缺口再指导下一轮搜索。旧证据如果被推翻，也可以被替换或撤回，而不是一直堆在上下文里。 效果也是很明显的。 在 OfficeQA Pro 上，GLM-5.3-Flash 的准确率从 15.8% 提升到 60.2%；更难的 V2 从 4.4% 提升到 61.1%，还分别超过 Claude Code 和 Codex。 而且当语料库变大之后，LongHarness 的中位交互轮数只从 22 增加到 30，而 Claude Code 从 21 涨到 116。 以前大家更关心「能不能找到信息」，接下来会更关心哪些证据还有效，哪些结论需要更新，以及下一步到底还缺什么。 📎 arxiv: https://t.co/9ubp84vAcc
