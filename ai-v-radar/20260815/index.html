这周发布的新模型也太多了，一天研究一两个新模型，都没给我足够时间去实际体验😂，明显感觉这周是真的累啊，有点认知负载了。 关于 GLM-5.3 这次发布，我觉得最值得看的其实是它和 Kimi K3 放在一起对比。 模型规模差得非常大： GLM-5.3 基于约 743B 的 GLM-5 基座继续做后训练，激活参数大约 40B；Kimi K3 则是 2.8T 总参数、104B 激活参数。 Kimi K3 总参数接近 GLM-5.3 的 4 倍，但两者在 Agentic Coding 上已经打到很接近的位置。 按照 https://t.co/erBiE0pibI 官方这次给出的同场评测： Terminal-Bench 3.0：28.3 vs 17.4 DeepSWE：66.9 vs 67.5 AutomationBench：48.2 vs 46.7 GLM-5.3 在 Terminal 和自动化任务上更亮眼，Kimi K3 在 DeepSWE 这种长时软件工程任务上依然略高一点。 另外一个很明显的变化是 Cyber。 CyberGym 上 GLM-5.3 是 84.5 vs 80.0，ExploitBench 更是 54.4 vs 32.2，这也是为什么 https://t.co/erBiE0pibI 这次直接把 Cyber Defense 放进了模型定位里。 最后关注的点是 GLM-5.3 并没有换一个更大的新基座。 官方直接说这次核心就是继续 scale post-training。相比 GLM-5.2，Terminal-Bench 3.0 从 4.6 涨到 28.3，DeepSWE 从 46.2 涨到 66.9。 Kimi K3 选择用 2.8T 模型、新架构和原生多模态继续往上扩，GLM-5.3 则在 743B 级基座上继续把 Coding、Agent 和 Cyber 的后训练做深。 这两条路线放在一起看，可能比单纯比较谁的 benchmark 高几分更有意思。

给 Agent 加 Skill，有时候反而会让它做得更差。 微软研究院等团队这篇《Agent Skills Can Be Harmful》，专门研究 Skill 到底是怎么把 Agent 带偏的。 作者在 SkillsBench 和 SWE-Skills-Bench 中找到了 307 个 Skill 引发的问题：125 个直接导致任务失败，182 个让任务变得明显更慢、更贵。 一个挺意外的结果是，大多数失败并非 Skill 完全不相关。 恰恰是那些「看起来很适合」的 Skill，容易让 Agent 过度相信里面的模板和默认做法，最后漏掉当前任务真正要求的东西。68.8% 的功能性失败都属于这一类。 效率问题也很有意思。主要成本并非 Skill 文档本身太长，而是它让 Agent 多做了很多流程，尤其是反复验证和过重的实现步骤。 这篇工作算是对现在的 Skill 热潮是个挺好的提醒： Skill 的价值不能只看「有没有被调用」，还要看它在这个具体任务里有没有真的帮上忙。 以后成熟的 Agent Skill 系统，可能还需要一套自己的评估、回归测试和淘汰机制。 Skill 越多，管理 Skill 的能力反而越重要。 📎 arxiv: https://t.co/3xTi0jecVN
