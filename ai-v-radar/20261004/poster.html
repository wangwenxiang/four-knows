Jev API在Postgres中找到适配OLTP数据库的使用形态

引用｜又一个很疯狂的 Jev 用例！ 传统数据库过滤器需要精确、预定义的条件。但很多问题是语义性的： - 这篇文章主要是关于软件工程的吗？ - 哪个主题最能描述它？ - 它看起来有多深的技术含量？ 这些通常需要把行移到应用代码中，调用模型，解析输出，再把结果写回。 pg-jev 是一个开源 Postgres 扩展，通过 SQL 函数暴露 Jev。 - jev() 可在 WHERE 中使用 - jev_prob() 返回概率 - jev_choice() 选择标签 - jev_score() 按有序等级对行排序。 它不需要向量列或嵌入索引。 在底层，pg-jev 会批处理行，将它们发送给 Jev，并返回带类型的答案，让 SQL 可以过滤、排序、分组，并与精确谓词组合。 下面的录屏是在 Postgres 中存储的真实 Hacker News 故事上运行的。 它先展示这些行，然后让 Jev 查找软件工程故事，按主题分类，并按技术深度排序。最后一个查询报告该数据库会话中的请求数、token、成本和缓存命中。 GitHub repo: https://t.co/6OD0nRMgfH （别忘了给它 star ⭐） Postgres 保留数据并控制查询，而 Jev 处理 SQL 无法表达为确定性条件的部分。 如果你想了解 Jev 底层在做什么，我还写了一篇实践指南，介绍如何完全在本地用开放模型构建 Jev 风格的模型。 请在下方阅读。
