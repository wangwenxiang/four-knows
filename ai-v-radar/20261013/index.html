Since the labels are known up front, Quail stores them in a trie and constrains decoding to paths in the trie. Quail stops decoding as soon as only one label is left, instead of decoding the full label. Quail also packs these few decode steps into the same forward passes as the prefill of other documents, so the GPU stays busy. On 12 classification queries, Quail is ~1.8x faster than a vLLM baseline!

由于标签是预先已知的，Quail 会将它们存储在 trie 中，并将解码限制在 trie 的路径内。Quail 不会解码完整标签，而是在只剩下一个标签时立即停止解码。Quail 还会把这几步解码打包进其他文档预填充的同一批前向传播中，让 GPU 保持忙碌。 在 12 个分类查询上，Quail 比 vLLM 基线快约 1.8 倍！

SSMs had the nice asymptotics but kept missing out on the inference goodies Transformers get for free like spec decode and quantization. Turns out we were just not caching the right thing. Same IO-aware trick behind FlashAttention, Mamba scan, paged KV. A lot of the big wins weren’t new architectures, just people taking memory IO seriously.

SSM 具有很好的渐近复杂度，但一直没能享受到 Transformer 天然具备的推理优化，比如 spec decode 和量化。结果发现，我们只是没有缓存正确的东西。这和 FlashAttention、Mamba scan、paged KV 背后的 IO-aware 技巧是同一思路。很多重大收益并不是来自新架构，而是来自人们开始认真对待内存 IO。

Ze-Wei (Johnny) Liou@zwljohnny

ReplaySSM now runs in production in GLM-5.3-Flash and Kimi-K3, and ships in TensorRT-LLM, vLLM, FlashInfer, and SGLang! It speeds up standard decoding (up to 1.47x) and speculative decoding (up to 2.1x), and now also enables a low-precision SSM state whose rounding error never propagates through the recurrence. Building on our earlier ReplaySSM work, we collaborated with @NVIDIA to pin down what the method really unlocks. Caching SSM inputs instead of the state is what ReplaySSM does. What it changes is that computing the output and updating the state can be separated during decoding. All three gains follow from that separation. Joint blog post, paper, and code with @NVIDIA and @tri_dao 👇

ReplaySSM 现在已在 GLM-5.3-Flash 和 Kimi-K3 的生产环境中运行，并已集成到 TensorRT-LLM、vLLM、FlashInfer 和 SGLang 中！ 它能加速标准解码（最高 1.47 倍）和推测解码（最高 2.1 倍），现在还支持低精度 SSM 状态，其舍入误差永远不会通过递归传播。 在我们此前 ReplaySSM 工作的基础上，我们与 @NVIDIA 合作，明确了这一方法真正释放的能力。ReplaySSM 做的是缓存 SSM 输入而不是状态。它带来的变化是，在解码期间可以将输出计算与状态更新分离。所有三项收益都源于这种分离。 与 @NVIDIA 和 @tri_dao 联合发布的博客、论文和代码 👇

两个今天能力差不多的 Agent，跑上一段时间后，可能会拉开非常大的差距。 Meta 等团队这篇《Agent Plasticity》，想测的就是一件事： Agent 到底有多会「从经验里变强」。 作者让模型权重保持不变，只允许 Agent 根据过去的成功和失败，持续修改自己的 Memory、Skills、策略和 Python 工具。 然后每隔一段时间，用全新的任务测试它，看这些经验有没有真正留下来。 论文提出了一个指标叫「Agent Plasticity」： 既看 Agent 最终提升了多少，也看为了获得这些提升花了多少学习成本。 实验覆盖 Chess、Go、Hex 和 NetHack。结果是不同前沿模型即使拿到类似的反馈和学习机会，自我改进曲线也差得非常大。 比如 Claude Fable 5 最终能力最高，但 GPT-5.6 Sol 的「学习效率」反而更高。 还有一些模型反复积累经验，表现几乎没涨，甚至下降。 进一步分析发现，弱自我改进 Agent 的一个典型问题，是明明已经存下了相关 Skill 和 Memory，执行时却根本想不起来用；而更强的 Agent 即使用上经验，也还会遇到经验质量和泛化的问题。 所以我觉得「Agent 有多强」和「Agent 有多会学习」以后可能会变成两个完全不同的指标。 真正的自进化能力，看的可能不只是一次 benchmark 能拿多少分，而是经历 10 次、100 次任务之后，它能不能把踩过的坑稳定变成下一次的能力。 📎 arxiv: https://t.co/VxSQ3o4EB8
