Agent 在不断进化，但训练它的环境，很多时候还停在原地。 Google Cloud AI Research 等团队这篇 EnvHarness，开始把「Harness」放到环境这一侧。 传统 benchmark 的任务和规则通常是固定的。Agent 变强以后，原来的环境很快失去训练价值，也很难针对它当前最薄弱的能力继续出题。 EnvHarness 会在现有环境外加一层可编程组件，通过改变初始状态、交互规则，或者组合多个任务，动态生成更适合当前 Agent 的训练环境。 更关键的是，它保留原来的环境逻辑和 verifier，所以不用重新解决「新生成任务到底有没有正确答案」这个麻烦。 配套的 EnvRigger 会观察 Agent 的成功和失败轨迹，找到具体弱点，再自动生成针对性的环境，跑新的 rollout 验证效果。 实验覆盖 ALFWorld、WebArena、SWE-bench Verified、OfficeQA 和 SpreadsheetBench 五个 benchmark。使用 EnvHarness 生成的环境学习后，held-out 任务最高提升 9 个点，同时执行步骤减少 9.8%；用于 RL 时，提升最高达到 6.5 个点。 这篇最有价值的地方在于，它把 Agent 自进化又扩了一层： Agent 可以根据环境学习，环境也可以根据 Agent 暴露出的弱点继续变化。 以后持续进化的系统会同时维护两个循环，Agent 在变强，训练它的世界也跟着一起变。 📎 arxiv: https://t.co/Om5FmkL5DG

One of the interesting properties we’ve observed around schema-guided, complex document extraction tasks 📑 is that coding agent harnesses are good baselines (in terms of cost/accuracy) for longer documents. We tested Claude Code and Codex, along with specialized OCR tools (including LlamaParse) and raw VLMs. * On short documents, specialized OCR tools are generally a fraction of the cost of coding agents, with equivalent or higher accuracy * On longer documents, coding agents are a bit closer to the cost/accuracy Pareto curve (see bottom graph) It’s an interesting result, though ultimately not surprising. Complex document extraction is a specialized reasoning task, and coding agents are effectively generalized reasoning harnesses. Over long documents, coding agents have more room to use a variety of tools to search snippets of the document instead of loading the entire document into context. They can also make use of prompt caching to reduce total token cost even as it expands multi-step reasoning. On the flip side, they do generate a baseline degree of token usage that proves to be wasteful for shorter docs compared to specialized extractors. This specific graph is in our Appendix D in the ParseBench paper, come check it out! ArXiv: https://t.co/s5azzQVGoZ ExtractBench: https://t.co/VapjcfLa1B

我们在围绕 schema 引导的复杂文档抽取任务 📑 中观察到一个有趣特性：对于较长文档，编码智能体框架在成本/准确率方面是不错的基线。 我们测试了 Claude Code 和 Codex，以及专门的 OCR 工具（包括 LlamaParse）和原始 VLM。 * 对于短文档，专门的 OCR 工具通常只需编码智能体几分之一的成本，准确率相当或更高 * 对于较长文档，编码智能体在成本/准确率帕累托曲线上更接近一些（见底部图表） 这是个有趣的结果，不过最终并不意外。复杂文档抽取是一种专门的推理任务，而编码智能体本质上是通用推理框架。面对长文档时，编码智能体有更多空间使用多种工具来搜索文档片段，而不是把整篇文档加载进上下文。它们还可以利用 prompt 缓存来降低总 token 成本，即便多步推理规模扩大。另一方面，相比专门抽取器，它们会产生一定的基线 token 用量，对短文档来说显得浪费。 这张具体图表位于 ParseBench 论文的附录 D，欢迎查看！ ArXiv: https://t.co/s5azzQVGoZ ExtractBench: https://t.co/VapjcfLa1B

我们一直在追最强模型又变强了多少，但这篇文章让我开始更关注另一条曲线。 同样水平的智能，到底在以多快的速度变便宜。 作者统计发现，今年 2 月还要大约 1.22 美元完成的任务，现在同等能力只需要 0.022 美元。 不到半年，便宜了约 56 倍。 这件事带来的变化会比模型在 Benchmark 再涨几分更大。 当一次调用便宜到几分钱，很多以前舍不得做的事情都可以直接暴力规模化。 不是抽样读 100 篇论文，而是把 1 万篇全部读完。 一个任务也不用只跑一次，可以跑三遍、五遍，再互相验证。 不过有意思的是，智能变便宜以后，我们花在 AI 上的钱可能反而更多。 因为真正爆发的，会是以前「太贵所以根本没人做」的那些任务。 如果智能真的以这个速度商品化，以后最稀缺的会是知道该让 AI 做什么，有可靠的 Ground Truth，以及能把大量智能组织起来的系统。 文章 https://t.co/FhjKZY2H26

we've been iterating a lot on how DocWriter internally represents a user's writing style! the naive approach is to dump all a user's prior writing in context and pray the AI figures out how to sound like them. this doesn't really work. and the user can't just manually specify their style either, because nobody knows what their meaningful writing preferences (for an AI agent) actually are. so we've built a multi-agent pipeline that runs lexical, grammatical, and discourse analyses on the user's writing, extracts specific patterns with evidence, and then surfaces them in a UI where the user can confirm or reject each pattern by comparing two passages side by side TBD on how well it performs in our next round of user studies 😆 it feels like we are really trying to do anything possible to avoid fine-tuning, but perhaps we need to bite the bullet eventually

我们一直在反复迭代 DocWriter 内部表示用户写作风格的方式！ 最朴素的做法是把用户过去所有写作都塞进上下文，然后祈祷 AI 能自己琢磨出怎么写得像他们。但这其实行不通。用户也不能手动指定自己的风格，因为没人真正知道自己对 AI agent 来说有意义的写作偏好到底是什么。 所以我们构建了一条多智能体流水线，对用户写作进行词汇、语法和篇章分析，提取带证据的具体模式，然后在 UI 中展示给用户，让他们通过并排比较两段文字来确认或拒绝每个模式。 下一轮用户研究中表现如何还有待观察 😆 感觉我们真的在竭尽所能避免微调，但也许最终还是得硬着头皮上
