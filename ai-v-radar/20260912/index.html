An agent matched human decisions 94% of the time. The 6% is the interesting part. A customer of ours has around 150,000 employees and a policy that lets teams request discounts. Marketing wants one for an event. Sales wants one to close a deal. The volume got so large globally that they had a dedicated team whose entire job was approving or denying those requests. Before trusting agents with it, they ran a backwards test. Last 30 days, what would the agent have approved or denied? 94% match with what the humans actually did. Their reaction was not let us automate everything. It was: if we can find the other 6% and route it to a person, we can roll this out. They now spend about 3% of the time they used to spend on it.

一个 agent 在 94% 的情况下做出了与人类一致的决策。 有意思的是剩下的 6%。 我们的一位客户约有 15 万名员工，并有一项政策允许团队申请折扣。市场团队想为活动申请折扣，销售团队想用折扣促成交易。 全球范围内申请量变得非常大，以至于他们有一个专门团队，全部工作就是批准或拒绝这些申请。 在信任 agent 处理这件事之前，他们做了一次回溯测试。过去 30 天里，agent 会批准或拒绝哪些申请？ 与人类实际决策的匹配率为 94%。 他们的反应不是“让我们把一切都自动化”。而是：如果我们能找出另外 6%，并把它交给人工处理，就可以上线。 现在他们在这件事上花的时间大约只有过去的 3%。

Hey ████, I think there is room for both. 1. Prototypes and other throw-away code can be treated as totally black box. If you’re going to throw it away anyway, and if the blast radius of it breaking is low, it doesn’t need to be perfect. 2. Production code written by Claude should have a higher bar than if it was written by a human. At Anthropic, we have many guardrails in place to make sure this is happening: lots of lint rules, lots of tests, Claude-driven end to end tests, Claude-powered fuzzers running daily, automated code reviews and security reviews, automated code refactoring, and so on. Without these, you can end up with a mess that is hard to maintain down the line. Luckily, the model makes it increasingly easy to do these well — run a few daily routines, use Claude Code Review, etc. Your job is to hold the bar on code quality. If Claude’s code doesn’t meet the bar, try: - Using the latest frontier model (Opus 5 or Fable 5.1) - Increase effort to high or xhigh - Invest in your CLAUDE.md and skills to succinctly teach Claude how to work in your codebase If all else fails, steer Claude more when you work with it, or have Claude fix accumulated debt and rewrite your codebase to make it easier to work with. Or, wait for the next model. Best, Boris

Both leading companies are willing to impose safety gates unilaterally -- requirements that need to be met before releasing a model or scaling up training. They'll start subjecting themselves to more challenging gates as people get increasingly spooked by progress. But this only leads to a minor slowdown. Safety evals will be benchmaxed, and there will be plenty of unknown unknowns. A bigger slowdown would be helpful for scientific understanding and for societal adjustment. AI-2040 proposes some stronger slowdowns, such as limiting R&D and training compute and requiring human understanding. But adopting these unilaterally would put a company at a serious disadvantage, allowing competitors to pull ahead. So that's where you need a broader agreement.

两家领先公司都愿意单方面设置安全关卡，即在发布模型或扩大训练规模前必须满足的要求。随着人们越来越被进展吓到，它们会开始让自己接受更具挑战性的关卡。但这只会带来轻微放缓。安全评估会被刷到极限，而且还会有大量未知的未知。 更大幅度的放缓将有助于科学理解和社会适应。AI-2040 提出了一些更强的放缓措施，例如限制研发和训练算力，并要求人类能够理解。但单方面采用这些措施会让公司处于严重劣势，使竞争对手得以领先。因此，这就需要更广泛的协议。
