Jerry Liu@jerryjliu0

Introducing ExtractBenchPro: the most challenging benchmark for real-world document extraction. We see a massive long tail of document complexity in terms of use cases brought on from our customers, that are completely unsolved from a price-performance standpoint. These include trial balances, well logs, canvass binders, site plan reviews, duty reconciliations, loss runs, and more. Most existing extraction benchmarks are saturated by the frontier models (our cheapest modes now score 93%+ on ExtractBench). So there is enormous economic value in building a complex extraction benchmark that reflects this long-tail of knowledge work. We spent a long time curating the most complex elements that we saw from real world extraction use cases: ✅ Document conventions: containing legends or rules where the rest of the document should be interpreted ✅ Density of internal jargon: specific definitions that must be cross-referenced within a doc ✅ Aggregation and reasoning: beyond returning exact values on a page, infer values derived from aggregating multiple sources of information ✅ Drawn relations: complex diagrams like procedures and circuits ✅ Charts inside documents: read precise points within a chart ✅ Long chart sheets: some data series like well logs cram all this data into an extremely long page Within the industries where document extraction is relevant, even small mistakes can have enormous negative impacts. Therefore our headline evaluation metric is based on perfect documents: the proportion of docs with perfect (100%) value f1 score. (Besides this we also measure value f1 and grounded f1) It’s an extremely hard task for even the latest frontier models to solve, topping out at ~58% or so in Value F1 score for Codex with Astra - which is quite good but extremely expensive (almost $1 per page!) Our LlamaParse agentic/agentic plus modes are 20-40% and cover the left side of the Pareto frontier, at price ranges that are feasible for full production use. ExtractBenchPro is available today as a website/technical blog, and also on Github and HuggingFace. Check it out! Blog: https://t.co/bwxs86iS1d Website: https://t.co/uRrFNU1Fqo Hugging Face: https://t.co/1VImPRTorq Github (is ExtractBench): https://t.co/auzmOGhsaB

推出 ExtractBenchPro：面向真实世界文档提取、挑战性最高的基准测试。 客户带来的应用场景中，存在大量复杂文档的长尾需求，从性价比角度看，这些需求仍完全没有得到解决。例如试算平衡表、测井记录、拉票资料册、场地规划审查、关税对账、理赔历史记录等。 前沿模型在大多数现有提取基准上的表现已接近饱和（我们最便宜的模式如今在 ExtractBench 上也能达到 93% 以上）。因此，构建一个反映这类知识工作长尾需求的复杂提取基准，具有巨大的经济价值。 我们花了很长时间，从真实提取场景中筛选出最复杂的要素： ✅ 文档约定：包含图例或规则，解读文档其余内容时必须遵循 ✅ 内部术语密度：包含特定定义，需要在文档内交叉查阅 ✅ 汇总与推理：不只是返回页面上的原始数值，还要汇总多个信息来源并推导结果 ✅ 图示关系：流程图、电路图等复杂图示 ✅ 文档内图表：精确读取图表中的数据点 ✅ 超长图表页：测井记录等数据序列会将大量数据塞进极长的单页 在需要文档提取的行业中，即使很小的错误也可能造成严重后果。因此，我们的核心评估指标以完全正确的文档为依据：数值 F1 得分达到满分（100%）的文档占比。 （此外，我们还衡量数值 F1 和有据可依的 F1 得分） 即使对最新的前沿模型而言，这项任务也极其困难。使用 Astra 的 Codex，数值 F1 得分最高也只有约 58%。这个成绩相当不错，但成本极高（每页接近 1 美元！）。我们的 LlamaParse agentic/agentic plus 模式得分为 20%–40%，位于帕累托前沿的低成本一侧，价格适合全面投入生产使用。 ExtractBenchPro 今天已通过网站和技术博客发布，同时上线 Github 和 HuggingFace。欢迎查看！ 博客：https://t.co/bwxs86iS1d 网站：https://t.co/uRrFNU1Fqo Hugging Face：https://t.co/1VImPRTorq Github（仓库名为 ExtractBench）：https://t.co/auzmOGhsaB
